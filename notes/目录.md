各部分是干什么的
1. 根目录

放项目级别的说明和配置。

README.md

项目总说明。
后面你做简历项目时，这个文件很重要。别人先看这个。

.env

放私密配置，比如 API Key。
这个文件不要上传到 GitHub。

.env.example

给未来的你或别人看，说明要配置哪些环境变量，但不放真实密钥。

requirements.txt

pip 依赖清单。
适合快速安装。

environment.yml

conda 环境配置文件。
既然你用 conda，这个最好保留，方便以后复现环境。

2. src/

这是你的主代码区，核心逻辑都在这里。

day1_structured_output.py 到 day6_logging.py

前一周按天推进时，建议先保留这种“按天编号”的文件。
好处是：

很适合学习阶段回看
你能看到自己每天多了什么
不会一开始就过度抽象

但后面稳定后，真正可复用的逻辑要慢慢抽到 core/、agents/、tools/ 里。

3. src/core/

放“底层公共模块”。

llm.py

统一封装模型调用。
以后你换模型、改参数、做重试，都只改这一处。

prompts.py

集中放 system prompt、模板 prompt。
不要把 prompt 散落在各个文件里。

schemas.py

放 Pydantic 数据结构。
比如：

RouterOutput
ToolCall
RagAnswer
WorkflowState
config.py

统一管理配置。
比如模型名、top_k、日志路径、是否开启 debug。

utils.py

小工具函数。
比如读写 jsonl、时间戳生成、文本清洗。

4. src/agents/

放“面向任务的 Agent”。

router_agent.py

做任务分类。
比如判断用户输入属于：

chat
search
extract
tool_needed
rag_agent.py

做文档问答。
后面第 2 周的主角。

workflow_agent.py

做多步骤流程。
后面第 3、4 周会更重要。

这里的原则是：

agent 负责决策与编排，不负责底层细节。

5. src/tools/

放工具函数和工具注册逻辑。

weather.py

一个假工具或真实天气工具。

search_notes.py

搜索本地笔记。

retrieve_docs.py

把 RAG 的检索包装成工具。

registry.py

统一注册工具，让 Agent 能知道有哪些工具可用。

这里你会慢慢体会到一个很重要的工程习惯：

工具定义和 Agent 主流程分开。

这样以后调试“是模型没选对工具，还是工具本身有 bug”会容易很多。

6. src/rag/

这是第 2 周的核心区。

loader.py

负责读原始文档。
比如 txt、md、pdf。

chunking.py

切块逻辑。
比如 chunk 大小、overlap、metadata。

embedding.py

把文本转向量。

indexer.py

建立向量索引。

retriever.py

输入 query，返回 top-k 文档块。

这里单独拆出来很值，因为后面 RAG 最常出问题的地方就在这一层：

文档解析
切块
检索
7. src/workflow/

这是第 3 周的核心区。

state.py

定义状态对象。
比如：

user_query
task_type
retrieved_chunks
draft_answer
final_answer
approval_required
nodes.py

每个节点做什么。

edges.py

流程转移条件。

graph.py

最终把流程连起来。

这个拆法很适合你后面引入 LangGraph，因为思路是一致的。

8. src/eval/

这是很多人忽略，但你后面做简历项目很加分的部分。

evaluator.py

跑评测。

metrics.py

定义指标，比如：

回答正确性
工具选择正确性
是否带引用
无依据是否拒答
cases_loader.py

读取评测样本。

你后面若想做“工程/评估型项目”，这块会很重要。

9. src/app/

放对外接口和演示入口。

api.py

FastAPI 接口。
比如：

POST /chat
GET /health
streamlit_app.py

快速做网页 demo。
适合后期展示。

10. data/

放数据，不放代码。

raw/

原始文档。
不要直接修改。

processed/

清洗后、切块后的中间数据。

vector_store/

存向量索引。

eval/

评测样本。
比如 jsonl：

input
expected
category
11. logs/

放运行记录。

traces/

保存每轮 Agent 执行轨迹。
比如：

user_input
chosen_tools
tool_args
final_output
runs/

放每次实验运行的汇总日志。

errors/

单独记录错误日志，排查方便。

你后面会发现，没有日志，Agent 系统很难调。

12. notes/

放你的学习笔记和复盘。

这部分不要小看，它其实是你“能不能讲清楚项目”的基础。

比如：

day1_notes.md
weekly_review.md
mcp_basics.md
13. demo/

放展示材料。

screenshots/

界面截图。

recordings/

录屏。

sample_inputs.md

准备演示时的示例输入。

后面面试、写 README、发作品时都能直接用。

14. tests/

放测试代码。

现在你不用写得很重，但至少要逐渐养成：

Router 测试
Tool 测试
RAG 检索测试
Workflow 流程测试
15. scripts/

放运行脚本，避免每次手敲长命令。

比如：

启动 API
启动 demo
构建索引
